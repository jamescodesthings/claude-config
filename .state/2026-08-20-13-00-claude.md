### Phase 6: installer output capture and logging (2026-08-20)

Triggered by James: the vendor and plugin installers printed raw to the console in their own formatting, and there was no record of a run to look at when one failed.

- [x] Added `run_logged` to `shared/tools/lib`: captures both output streams of a third-party command to `.cache/logs/<run-id>/<label>.log`, closes stdin, returns the command's own exit status so every existing `|| warn` chain is unchanged
- [x] Replaced every `&> /dev/null` in the installers and uninstallers with it. That idiom cured the console noise by destroying the evidence: a failed step said that it failed and nothing said why
- [x] On failure, the tail of the step's output prints inline, scoped to that step. `run_logged` records the log's line count before running, because log files are appended to across a script's whole run and a plain tail would show the previous step's output too
- [x] One log directory per run, id exported so sub-installers (separate processes) share it. `latest` symlink, `make logs`, last 10 runs kept
- [x] `--debug` (stream captured output live) and `--trace` (adds `setopt xtrace`) on `./install`, both `<cli>/install`, and both uninstallers. Exported, so they reach every child. Unknown flags are still a hard error. `make install-debug` / `make install-trace`
- [x] `curl` diagnostics from `fetch_installer` go to `downloads.log` instead of the console, with the same inline tail on failure
- [x] Success messages carry versions: `cli_version` pulls the first dotted-numeric token out of `--version`, since CLIs pad it with their own name and a build tag. claude-monitor's version comes from `uv tool list`, its only source
- [x] `install-rtk` now fetches through `fetch_installer` like the two CLI bootstrappers, so it gets the shebang check and the auditable cached copy instead of its own TMPDIR download
- [x] `antigravity/tools/install-caveman` lost its local `timeout_cmd` array, which duplicated `run_guarded` one copy behind
- [x] Three zsh traps hit and fixed during this work, each documented at the point of use:
  - `local status` is a runtime error: `$status` is a read-only special parameter aliased to `$?`. Renamed to `rc`
  - `setopt xtrace` inside a function is undone when the function returns (zsh saves and restores the option per call). Tracing is now switched on at script top level with `trace_enabled && setopt xtrace`
  - In a glob qualifier, `^` inverts every qualifier that follows it, so `*(N/^@On)` negated the sort as well as the symlink test and `prune_run_logs` kept the OLDEST runs. Now `*(N/On^@)`
