`skill-graduate` and `memory-graduate` move something from the encrypted WIP tier into the plaintext, publicly-committed tier. I never invoke these myself, even under crack-on/no-confirmation mode — not batch-pre-approved, not "seems obviously ready."

**Why:** James stated this explicitly on 2026-08-17 while specifying the WIP command family: graduation is a judgment call about what's safe to make public in a repo that's actually public, and it must stay a deliberate, manual action he performs himself.

**How to apply:** when WIP content looks ready to graduate, tell James it's ready and hand him the exact command (`skill-graduate <slug> <real-name>` / `memory-graduate <slug> <real-name>`) — do not run it, do not offer to run it "to save a step." This is a standing exception alongside irreversible/destructive actions in [[feedback_no_confirmation]].
